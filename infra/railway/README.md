# Railway staging

This directory defines SiftCut's persistent, manually deployed staging stack.
Only `web` receives a Railway-generated public domain. PostgreSQL, `migrator`,
and `api` remain on Railway private networking.

## Service configuration

Create the `siftcut-staging` project and `staging` environment. Create four
services from this repository, initially pinned to the acceptance feature
branch, and assign each service its matching config-as-code file:

| Service | Config path | Public domain |
| --- | --- | --- |
| `postgres` | `/infra/railway/postgres/railway.toml` | No |
| `migrator` | `/infra/railway/migrator/railway.toml` | No |
| `api` | `/infra/railway/api/railway.toml` | No |
| `web` | `/infra/railway/web/railway.toml` | Yes, generated by Railway |

Disable automatic GitHub deployments for all four services. Keep `api` and
`web` on the smallest always-on staging instances during acceptance. Attach a
persistent volume to `/var/lib/postgresql/data` on `postgres`.

Enter secret values only in Railway's masked variable controls. Never put
values in this repository, shell history, deployment screenshots, or support
logs.

### PostgreSQL

- `POSTGRES_DB=siftcut`
- `POSTGRES_USER=postgres`
- `POSTGRES_PASSWORD` (masked, generated)
- `MIGRATOR_PASSWORD` (masked, generated independently)
- `API_PASSWORD` (masked, generated independently)

### Migrator

- `MIGRATOR_DATABASE_URL=postgresql://siftcut_migrator:<masked>@postgres.railway.internal:5432/siftcut`

The migrator is a private run-to-completion service. A successful deployment
must exit zero after printing `migration_complete`.

### API

- `NODE_ENV=production`
- `PORT=3000`
- `DATABASE_URL=postgresql://siftcut_api:<masked>@postgres.railway.internal:5432/siftcut`
- `CLERK_ISSUER` for the Clerk instance
- `CLERK_AUDIENCE=siftcut-api`
- `CLERK_AUTHORIZED_PARTIES=https://<generated-web-domain>`
- `CLERK_SECRET_KEY` (masked)
- `CLERK_WEBHOOK_SIGNING_SECRET` (masked)

Do not set migrator or PostgreSQL administrator credentials on `api`.

### Web

- `API_UPSTREAM=http://api.railway.internal:3000`
- `VITE_CLERK_PUBLISHABLE_KEY`

`VITE_API_URL` is intentionally unset in staging so browser requests use the
public web origin and Caddy's private reverse proxy.

The browser uses Clerk's session token, not a named custom JWT template.
Customize the Clerk session token with `{"aud":"siftcut-api"}`. A named custom
JWT cannot be used here because Clerk does not include the session-bound `sid`
and `fva` claims or the active v2 `o` claim that this API validates.

## Deployment order

Railway push deployments do not order dependent services. For the initial
deployment and every schema-bearing release, deploy and verify exactly:

1. `postgres` is healthy and its volume is mounted.
2. `migrator` exits zero.
3. `api` passes its private `/ready` healthcheck.
4. `web` passes `/_health`; then verify public `/health` and `/ready`.

Stop on the first failure. Inspect only sanitized logs. Do not take screenshots
while a secret field, token, connection string, or personal test data is
visible.

After merge, repoint each service to `master`, keep automatic deployments
disabled, and redeploy in the same order. Rollback restores the previous
`api`/`web` deployments and disables the Clerk webhook if needed; it does not
delete staging data or rewrite migration checksums.
